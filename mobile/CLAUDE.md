# Kelal Studio — Mobile (Flutter)

Bilingual (Amharic/English) AI content-generation app. This is the
load-bearing surface of the product — see `../docs/Kelal_Studio_PRD.pdf`.
Full domain skills live in `.claude/skills/`; read the relevant one before
touching architecture, security, performance, typography, or tests — this
file is facts, not procedures.

## Commands

```
fvm flutter pub get                                          # deps
fvm flutter gen-l10n                                           # regenerate lib/core/l10n/gen/ after editing an .arb file
dart run build_runner build --delete-conflicting-outputs      # codegen (freezed/injectable/retrofit/drift/envied)
fvm flutter analyze                                            # must be clean before /commit
fvm flutter test --coverage                                    # unit + widget + golden
fvm flutter test --tags golden --update-goldens                # only when a visual change is intentional
fvm flutter run                                                 # local run, defaults to the mock API (Env.useMockApi)
fvm flutter run --dart-define=USE_MOCK_API=false --dart-define=API_BASE_URL=<url>   # against a real backend
```

Always prefix Flutter/Dart commands with `fvm` — the pinned SDK
(`.fvmrc`) is what CI and golden-test baselines assume; running the
system Flutter can silently shift golden pixels or codegen output.

## Architecture (non-negotiable — see flutter-architecture skill for detail)

- Clean Architecture, **feature-first**: `lib/features/<name>/{data,domain,presentation}`.
- `domain/` is pure Dart. No `flutter`, `flutter_bloc`, `dio`, `drift` imports there, ever.
- One usecase class per use case (`call()` method). Blocs call use cases, never repositories.
- Every value that can fail crosses a public API as `Result<Failure, T>`
  (`core/error/result.dart`), never a thrown exception, never a nullable
  "maybe it worked" return.
- `core/render_engine` is the **single** paint routine for both the live
  canvas editor and final export — never add a second rendering path. This
  is the PRD's #1-rated risk ("preview doesn't match export") made
  structurally impossible; do not compromise it for convenience.
- DI: `get_it` + `injectable`. Run build_runner after adding any
  `@injectable`/`@lazySingleton`/`@module`.
- Mock vs real data source selection lives in one `@module` per feature
  (e.g. `features/auth/data/datasources/auth_datasource_module.dart`),
  gated on `Env.useMockApi`. Nothing else should instantiate a `Fake*` or
  `Real*` data source directly.

## State management

- `flutter_bloc`: Bloc for anything touching domain logic, Cubit only for
  trivial UI-local state (a toggle, a text field's dirty flag).
- Every event handler gets a deliberate `bloc_concurrency` transformer —
  see `flutter-state-management` skill for the full table. Never leave a
  handler on the implicit `concurrent()` default without having consciously
  ruled out a race.

## What NOT to do

- Don't hand-edit generated files (`*.g.dart`, `*.freezed.dart`,
  `*.config.dart`) — they're gitignored and regenerated by build_runner.
- Don't call `dio`, a repository, or a data source from a widget —
  everything goes through a Bloc/Cubit → use case → repository.
- Don't add a provider API key, or any secret, to client code — see
  `flutter-security` skill. There should be zero AI-provider credentials
  anywhere under `mobile/`.
- Don't bypass `/commit` with a raw `git commit` — a root-level hook blocks
  it anyway (see root `CLAUDE.md`), but don't try to work around it either.
- Don't silently resolve one of the PRD's still-open questions (aspect
  ratios, Amharic input method, Ethiopian calendar, etc.) — flag it and
  ask. See `flutter-architecture` skill. (App-interface localization,
  OQ-14, is no longer open — see Localization below.)
- Don't touch `web/` or `backend/` from this package — they don't exist
  yet and are out of scope for mobile work.
- Don't add a dependency with `^` or a loose range, and never `any` — every
  version in `pubspec.yaml` is exact, deliberately (see the comment at the
  top of that file). Bumping a package is its own reviewed change.

## Design tokens

Real values pulled from the Kelal Studio Figma file
(`0dIrGk2LyVEseP6Tz1KxMa`), encoded in `lib/core/theme/`. Never hardcode a
hex/px value in a widget — use `context.colors.*`, `AppTypography.*`,
`AppSpacing.*`, `AppRadius.*`. Before building a new screen or component,
read `flutter-design-system` skill and pull the specific Figma node with
`get_design_context` — don't approximate from memory of another component.

## Localization & dark mode

- `AppLocalizations` (generated from `lib/core/l10n/arb/app_en.arb` /
  `app_am.arb` via `flutter gen-l10n`, config in `l10n.yaml`). Add a key to
  **both** ARB files together — never let them drift out of sync. Every
  new Amharic string needs native-speaker review before shipping (PRD's
  own requirement for Amharic content); only `appTitle`/`appTagline` are
  pulled verbatim from Figma so far, everything else is a flagged
  best-effort placeholder — check `app_am.arb`'s file-level notes before
  trusting a translation is final.
- `LocaleCubit` (`core/l10n/locale_cubit.dart`) holds the user's explicit
  language choice (`null` = follow system); `ThemeCubit`
  (`core/theme/theme_cubit.dart`) holds light/dark/system. Both are
  `HydratedCubit`s — persisted, small UI prefs, exactly the case
  `flutter-state-management` calls out for `hydrated_bloc`. Read them via
  `context.watch`/`context.read`, never introduce a second source of
  truth for the current locale/theme.
- Any screen needs to feed `locale`/`themeMode` into `MaterialApp` from
  these cubits to actually respond to toggling — see `lib/app.dart` for
  the real wiring and `test/features/auth/presentation/pages/login_page_test.dart`
  for why a test's `wrap()` helper must do the same (a `wrap()` that
  hardcodes `theme`/`locale` instead of wiring the cubits will pass
  trivially while the toggle buttons silently do nothing).

## Golden testing

Use `goldenThemeTest` (`test/goldens/golden_helpers.dart`) for every new
component golden — one call crosses every named variant with both light
and dark automatically. See `test/goldens/primary_button_golden_test.dart`
for the reference usage. Don't hand-write a `GoldenTestGroup` with
separate light/dark `GoldenTestScenario`s per variant; that's exactly the
duplication this helper exists to remove.

## Decisions log (so these aren't re-litigated per session)

- Android `minSdk 24` / iOS `13.0`, app id `com.kelalstudio.app`. (The
  original target was minSdk 21 for max reach on low-end devices, but
  Flutter 3.44.4's tooling itself enforces a 24 floor — it force-rewrites
  any lower value on every build; see the comment in
  `android/app/build.gradle.kts`. Revisit if a future Flutter/AGP version
  relaxes this.)
- Error handling: hand-rolled sealed `Result<Failure, T>`, not `fpdart`/`dartz`.
- Local DB: `drift`, not Isar (abandoned upstream) — drafts are
  device-local only in v1, no server sync (PRD §6.10).
- Navigation: plain `go_router` (string paths) until the route surface
  stabilizes past a couple more features, then adopt `go_router_builder`.
- Cert pinning: implemented but off by default — see `flutter-security` skill.
- All dependency versions are pinned exactly (no `^`, no `any`) — see the
  comment at the top of `pubspec.yaml`.
- App-interface localization (PRD OQ-14) is resolved: yes, localize the
  interface (not just generated content) — see Localization above.
